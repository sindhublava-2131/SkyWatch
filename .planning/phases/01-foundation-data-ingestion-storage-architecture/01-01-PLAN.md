# Plan 01-01: Foundation, Scaffolding, Profiles, Schemas, and Logging

## Goal
Establish the foundational project scaffolding, dual-profile runtime configurations (`modern` vs `lab`), single-source-of-truth canonical data schemas in `config/schemas.yaml`, structured pipeline logging with unique `run_id` tracking, and contract validation tests.

## Context & Requirements
- **HYG-01**: Ingested feeds must normalize to canonical schemas defined in `config/schemas.yaml`.
- **HYG-02**: Explicit UTC measurement and ingestion timestamps must be preserved on every record.
- **OPS-06**: Profile switching script and smoke tests between `modern` and `lab` execution profiles with environment validation.
- **OPS-07**: Structured run logging across all pipeline stages with unique run identifiers (`run_id`) and defined schema.
- **Python Syntax Floor**: Code must strictly respect Python 3.8+ syntax floor (`from __future__ import annotations`, `typing.Optional`, `typing.Dict`, no `match/case` statement) to ensure seamless execution under older lab Python runtimes.

### Task 2: Dual-Profile Environment Configurations & Profile Switcher
**Requirements:** OPS-06  
**Files to create:**
- `profiles/modern.env`
- `profiles/lab.env`
- `scripts/use_profile.sh`
- `src/skywatch/pipeline/profile.py`
- `tests/unit/test_profile.py`

**Steps:**
1. Create `profiles/modern.env`:
   - `SKYWATCH_PROFILE="modern"`
   - `HADOOP_HOME="/opt/bigdata/hadoop-3.4.3"`
   - `PIG_HOME="/opt/bigdata/pig-0.18.0"`
   - `SPARK_HOME="/opt/bigdata/spark-4.3.0-bin-hadoop3"`
   - `JAVA_HOME_PIG="/usr/lib/jvm/java-8-openjdk-amd64"`
   - `JAVA_HOME_SPARK="/usr/lib/jvm/java-17-openjdk-amd64"`
   - `JAVA_HOME="$JAVA_HOME_PIG"` (defaults to JDK 8 for Pig stability)
   - `HDFS_ROOT="/skywatch"`
   - `SKYWATCH_HTTP_TIMEOUT=20`
   - `SKYWATCH_MAX_RETRIES=5`
   - `SKYWATCH_FRESH_HOURS=3`
   - `SKYWATCH_STALE_HOURS=24`
2. Create `profiles/lab.env`:
   - `SKYWATCH_PROFILE="lab"`
   - `HADOOP_HOME="/opt/bigdata/hadoop-3.2.2"`
   - `PIG_HOME="/opt/bigdata/pig-0.18.0"`
   - `SPARK_HOME="/opt/bigdata/spark-3.2.2-bin-hadoop3.2"`
   - `JAVA_HOME_PIG="/usr/lib/jvm/java-8-openjdk-amd64"`
   - `JAVA_HOME_SPARK="/usr/lib/jvm/java-8-openjdk-amd64"`
   - `JAVA_HOME="$JAVA_HOME_PIG"`
   - `HDFS_ROOT="/skywatch"`
   - `SKYWATCH_HTTP_TIMEOUT=30`
   - `SKYWATCH_MAX_RETRIES=5`
   - `SKYWATCH_FRESH_HOURS=3`
   - `SKYWATCH_STALE_HOURS=24`
3. Create `scripts/use_profile.sh`:
   - Accepts argument `$1` (`modern` or `lab`). Defaults to `modern`.
   - Validates existence of `profiles/${1}.env`.
   - Sources environment and sets `SKYWATCH_PROFILE`.
   - Prints active configuration summary.
4. Implement `src/skywatch/pipeline/profile.py`:
   - Define dataclass `ProfileConfig` with fields: `profile_name`, `hadoop_home`, `pig_home`, `spark_home`, `java_home_pig`, `java_home_spark`, `hdfs_root`, `http_timeout`, `max_retries`.
   - Implement `load_profile(profile_name: Optional[str] = None) -> ProfileConfig` that reads from active environment or specified file.
   - Implement `validate_environment(config: ProfileConfig) -> Dict[str, bool]` to verify:
     - Java 8 verification: executes `$JAVA_HOME_PIG/bin/java -version` and verifies output matches `1.8.*`.
     - Spark Java verification: on `modern` checks >= 17, on `lab` checks == 1.8.
     - Graceful degradation flags when external Hadoop/Spark directories are not present locally.
5. Create `tests/unit/test_profile.py`:
   - Test profile loading for both `modern` and `lab`.
   - Test default fallback behavior when no profile is explicitly defined.
   - Test validation logic against simulated environment variables.

**Verification:**
`pytest tests/unit/test_profile.py`

**Steps:**

     - `delimiter: ","`
     - `has_header: true`

   - `weather`:
     - `partition_key: "ingest_dt"`
     - `delimiter: ","`
     - `has_header: true`
     - Fields: `record_key` (string, non-null), `location_id` (string, non-null), `latitude` (double, non-null), `longitude` (double, non-null), `temperature_c` (double, nullable), `humidity_pct` (double, nullable), `wind_speed` (double, nullable), `wind_unit` (string, non-null), `precipitation_mm` (double, nullable), `measurement_time_utc` (string, non-null), `ingestion_time_utc` (string, non-null), `source` (string, non-null), `data_kind` (string, non-null).

   - `get_schema(schema_name: str) -> Dict[str, Any]`
   - `get_column_names(schema_name: str) -> List[str]`
   - `validate_record_dict(record: Dict[str, Any], schema_name: str) -> Tuple[bool, Optional[str]]`
3. Create `tests/contract/test_schemas.py`:
   - Assert `config/schemas.yaml` exists and is valid YAML.
   - Assert `air_quality` contains `record_key`, explicit `measurement_time_utc`, `ingestion_time_utc`, `ingest_dt`.
   - Assert `weather` contains `record_key`, `measurement_time_utc`, `ingestion_time_utc`, `ingest_dt`.
   - Validate that `validate_record_dict` catches missing required keys and mismatched types.

**Verification:**
`pytest tests/contract/test_schemas.py`

### Task 4: Structured Logging Module with `run_id`
**Requirements:** OPS-07  
**Files to create:**
- `src/skywatch/pipeline/logging.py`
- `tests/unit/test_logging.py`

**Steps:**
1. Implement `src/skywatch/pipeline/logging.py`:
   - `generate_run_id() -> str`: Generates UUID4 hex string for each run.
   - Custom `PipelineLoggerAdapter` or JSON log formatter injecting:
     - `timestamp_utc`: ISO-8601 UTC timestamp.
     - `run_id`: Execution run identifier.
     - `level`: Log level (`INFO`, `WARN`, `ERROR`, `DEBUG`).
     - `component`: Calling module/component name.
     - `message`: Log text.
     - `extra`: Dictionary of contextual metrics (e.g. record counts, latencies).
   - Security redaction: regex/filter scrubbing `api_key`, `token`, `password`, `key` from all log strings and extra dictionaries.
   - Context manager `run_context(run_id: Optional[str] = None)` allowing pipeline runs to automatically scope child log calls to the current `run_id`.
2. Create `tests/unit/test_logging.py`:\n   - Test JSON output formatting includes required keys (`timestamp_utc`, `run_id`, `component`, `message`).
   - Test that sensitive API keys (e.g., `OPENAQ_API_KEY=testkey123`) are redacted with `***REDACTED***`.
   - Test context manager propagates `run_id`.

**Verification:**
`pytest tests/unit/test_logging.py`
