# Plan 01-03: Storage Architecture, Watermarking, Backfill & Automation

## Goal
Implement atomic local storage, the partitioned HDFS storage adapter with NameNode safemode pre-checks, per-sensor watermark state management with two-phase commit, chunked historical backfilling, the unified CLI (`discover`, `collect`, `backfill`), and automated scheduling via local cron and GitHub Actions.

## Context & Requirements
- **ING-05**: Support incremental collection using per-sensor watermarks committed atomically with file renames, and historical backfilling with chunked checkpointing (FR-11, FR-12).
- **ING-06**: Scheduled collection support via local cron script and GitHub Actions cron workflow (FR-13).
- **HYG-06**: Partitioned storage layout: `/raw/` and `/normalized/` partitioned by `ingest_dt=YYYY-MM-DD`; `/clean/` and `/analytics/` partitioned by `event_dt=YYYY-MM-DD` with idempotent uploads (FR-14, FR-15).
- **HYG-07**: Support offline execution mode running purely from cached local datasets and recorded mock fixtures (FR-16).
- **Atomicity Protocol**: Files must be written to `.tmp.{run_id}` and renamed via `os.replace` to prevent partial reads or corrupt state on interruption.

### Task 2: Partitioned HDFS Storage Adapter
**Requirements:** HYG-06, HYG-07  
**Files to create:**
- `src/skywatch/storage/hdfs_storage.py`
- Update `tests/integration/test_storage.py`

**Steps:**
1. Implement `src/skywatch/storage/hdfs_storage.py`:
   - Class `HDFSStorageAdapter`:
     - Constructor takes `hdfs_root: str = "/skywatch"`, `offline_dir: str = "data/local_hdfs"`.
     - Method `check_safemode() -> bool`:
       - Executes `hdfs dfsadmin -safemode get` via `subprocess.run(capture_output=True, timeout=5)`.
       - Returns `False` if safemode is OFF; returns `True` if safemode is ON.
       - Returns `True` (or offline flag) if `hdfs` binary not found or cluster unreachable.
     - Method `upload_partition(local_file_path: str, hdfs_partition_dir: str, run_id: str) -> bool`:
       - If HDFS is offline or safemode is ON: copies file to `{offline_dir}/{hdfs_partition_dir}` and logs warning without throwing exception (`HYG-07`).
       - If HDFS is online:
         - Stages upload: `hdfs dfs -mkdir -p /skywatch/_staging`.
         - Uploads to stage: `hdfs dfs -put -f {local_file_path} /skywatch/_staging/{run_id}_{filename}`.
         - Creates target directory: `hdfs dfs -mkdir -p {hdfs_partition_dir}``.
         - Moves to target: `hdfs dfs -mv /skywatch/_staging/{run_id}_{filename} {hdfs_partition_dir}/{filename}`.
     - Method `is_available() -> bool`: Quick ping to test HDFS CLI reachability.
2. In `tests/integration/test_storage.py`:
   - Test mock HDFS upload routes to `offline_dir` when HDFS CLI fails or is unreachable.
   - Test staging upload and rename commands formatting.

**Verification:**
`pytest tests/integration/test_storage.py`

### Task 3: Per-Sensor Watermark State Manager
**Requirements:** ING-05  
**Files to create:**
- `src/skywatch/storage/watermark.py`
- `tests/integration/test_watermark.py`

**Steps:**
1. Implement `src/skywatch/storage/watermark.py`:
   - Class `WatermarkManager`:
     - Manages `data/.watermarks.json`.
     - Structure:
       ```json
       {
         "updated_at_utc": "2026-11-22T08:30:00Z",
         "sensors": {
           "<sensor_id>": {
             "parameter": "pm25",
             "station_id": "2178",
             "last_measurement_utc": "2026-11-22T08:00:00Z",
             "last_run_id": "<uuid>",
             "records_ingested": 142
           }
         }
       }
       ```
     - Method `get_watermark(sensor_id: str) -> Optional[str]`: Returns `last_measurement_utc` or `None`.
     - Method `update_watermark(sensor_id: str, station_id: str, parameter: str, last_measurement_utc: str, record_count: int, run_id: str) -> None`: Updates in-memory dictionary.
     - Method `commit(run_id: str) -> None`:
       - Serializes state to JSON.
       - Writes to `data/.watermarks.json.tmp.{run_id}`.
       - Executes `os.replace` to `data/.watermarks.json`.
       - Two-phase guarantee: If pipeline crashes before `commit()`, watermark file is not updated.
2. Create `tests/integration/test_watermark.py`:
   - Test reading and writing watermarks.
   - Test crash simulation: uncommitted updates do not modify `data/.watermarks.json`.
   - Test loading corrupted or non-existent file gracefully initializes empty state.

**Verification:**
`pytest tests/integration/test_watermark.py`

### Task 4: Ingestion Orchestrator & Chunked Backfill Engine
**Requirements:** ING-01, ING-02, ING-04, ING-05, HYG-06, HYG-07  
**Files to create:**
- `src/skywatch/collector/collector.py`
- `tests/integration/test_collector_e2e.py`

**Steps:**
1. Implement `src/skywatch/collector/collector.py`:
   - Class `IngestionOrchestrator`:
     - Coordinates `OpenAQClient`, `WeatherClient`, `WatermarkManager`, `HDFSStorageAdapter`, validation, normalization, and deduplication.
     - Method `run_incremental_collection(run_id: Optional[str] = None, offline: bool = False) -> Dict[str, Any]`:
       - Loads `config/stations.json`.
       - For each station and sensor, retrieves watermark `last_measurement_utc`.
       - Fetches new readings (or fixtures if offline).
       - Saves unmodified raw responses and logs to `_manifest.csv`.
       - Normalizes, validates, and deduplicates records.
       - Writes normalized CSV to `data/normalized/air_quality/ingest_dt=YYYY-MM-DD/`.
       - Fetches corresponding weather data, normalizes, and writes to `data/normalized/weather/ingest_dt=YYYY-MM-DD/`.
       - Uploads to HDFS staging and target partition if HDFS available.
       - Atomically commits updated watermarks.
       - Returns collection summary metrics (records collected, rejected, duplicates, watermarks updated).
     - Method `run_chunked_backfill(start_date: str, end_date: str, chunk_days: int = 7, offline: bool = False) -> Dict[str, Any]`:
       - Divides `[start_date, end_date]` into 7-day windows.
       - Checkpoint file: `data/.backfill_checkpoint.json`.
       - Resumes from last uncompleted chunk if checkpoint exists.
       - Ingests measurements timeseries or precomputed hours (`/v3/sensors/{id}/hours`).
       - Writes normalized partitions and updates checkpoint after each successful chunk.
2. Create `tests/integration/test_collector_e2e.py`:
   - Run complete end-to-end collection in offline mode.
   - Assert raw JSON exists in `data/raw/`.
   - Assert entry appended to `data/raw/_manifest.csv`.
   - Assert normalized CSV exists in `data/normalized/` with valid schema.
   - Assert watermarks file updated.
   - Assert re-running collection produces 0 duplicate records.

**Verification:**
`pytest tests/integration/test_collector_e2e.py`

**Requirements:** ING-06

- `scripts/cron_collect.sh`
- `.github/workflows/scheduled-collect.yml`

**Steps:**
1. Create `scripts/cron_collect.sh`:
   - Bash script with lockfile mechanism:
     ```bash
     exec 200>/tmp/skywatch_collect.lock
     flock -n 200 || exit 1
     ```
   - Sources environment profile: `source profiles/modern.env`.
   - Runs `python -m skywatch.cli collect --mode incremental`.
   - Appends output to `/var/log/skywatch_cron.log` or project-local `data/logs/cron.log`.
2. Create `.github/workflows/scheduled-collect.yml`:
   - Schedule trigger: `schedule: - cron: '*/30 * * * *'`.
   - Workflow dispatch trigger: `workflow_dispatch`.
   - Steps:
     - Check out repo.
     - Set up Python 3.11.
     - Install requirements.
     - Run `python -m skywatch.cli collect --mode latest` with env `OPENAQ_API_KEY: ${{ secrets.OPENAQ_API_KEY }}`.
