# Plan 03-02: Spark Analytics Pipelines, Weather Correlation, Alert Engine & Simulation Fallback

## Goal
Implement the core Apache Spark analytical jobs and pure-Python simulation fallback engine: station summary statistics and pollution rankings (`station_statistics.py`), temporal hourly/daily trends with peak-hour detection (`trend_analysis.py`), hourly weather joins with Pearson correlation and confidence tiers (`weather_analysis.py`), 24-hour rolling CPCB AQI with 16h validity gating and suppression codes (`index_job.py`), alert and rolling median spike engine (`alert_engine.py`), cross-stage data quality audit (`quality_report.py`), and the master orchestrator (`spark_runner.py`) with golden reference verification (`test_spark_analytics.py`).

## Context & Requirements
- **SPK-01**: Calculate station summary statistics, pollution rankings, and identify cleanest vs most polluted hotspots (FR-20, NFR-03).
- **SPK-02**: Analyze hourly and daily trends, identifying peak pollution hours for each station (FR-21, NFR-04).
- **SPK-03**: Join air quality with weather metrics on station hour and calculate Pearson correlation coefficients with sample size n and confidence tier (FR-22, NFR-03).
- **SPK-04**: Calculate 24-hour rolling CPCB PM-based National AQI from regularized hourly means using linear interpolation and >=16 valid hours rule, emitting explicit suppression reasons when invalid (FR-23, NFR-02).
- **SPK-05**: Generate health alerts for Poor/Severe categories, and separate pipeline telemetry alerts for offline stations and stale readings (FR-24, NFR-01).
- **SPK-07**: Generate data quality report tracking accepted, rejected, and duplicate counts categorized by reason (FR-26, NFR-12).
- **SPK-08**: Compute rule-based rolling median spike detection flags (FR-27, NFR-03).
- **Dual-Mode Execution**: In environments with PySpark and JVM available, jobs execute distributed Spark operations; in zero-JVM, Windows, or CI environments, `_run_standalone_spark_fallback()` runs identical logic producing numerically equivalent results within epsilon < 1e-4.

<action>
1. Implement `src/skywatch/spark/weather_analysis.py`:
   - Implement compute_weather_correlation(df_air_hourly: DataFrame, df_weather: DataFrame) -> DataFrame:
     - Join hourly air quality and weather records on truncated UTC hour (date_trunc('hour', bucket_start_utc) == date_trunc('hour', measurement_time_utc)).
     - Iterate across weather variables: temperature_c, humidity_pct, wind_speed, precipitation_mm.
     - Group by station_id and pollutant (parameter), computing pearson_r via corr("average_value", var) rounded to 4 decimals, and sample_count n.
     - Assign confidence_tier: "High" if sample_count >= 100, "Medium" if 30 <= sample_count < 100, "Low" otherwise. If sample_count < 2 or variance is 0, set pearson_r to null and tier to "Low".
     - Union all variables into a single DataFrame matching schema weather_correlation.

2. Implement `src/skywatch/spark/index_job.py`:
   - Implement compute_cpcb_rolling_index(df_hourly: DataFrame) -> DataFrame:
     - Window definition: partition by station_id, parameter; order by unix timestamp of bucket_start_utc; rangeBetween -23 * 3600 and 0.
     - Count valid_hours over window.
     - When valid_hours >= 16: compute rolling_24h_avg = round(avg(average_value), 1).
     - When valid_hours < 16: set rolling_24h_avg = null, suppression_reason = "INSUFFICIENT_VALID_HOURS".
     - Apply CPCB subindex piecewise linear formula for pm25 and pm10.
     - Pivot/join PM2.5 and PM10 to compute overall AQI = max(subindex_pm25, subindex_pm10), category using classify(), dominant_pollutant, and is_partial flag.
     - Enrich records with station_name by joining station_id with station metadata from config/stations.json (or clean records).
     - Return DataFrame matching schema cpcb_index.

3. Implement unit tests in `tests/unit/test_weather_correlation.py`:
   - Test Pearson r calculation on controlled paired numeric lists.
   - Test confidence tier assignment: n=120 -> High, n=45 -> Medium, n=15 -> Low.
   - Test zero-variance and null handling returning null r with Low tier.
</action>

## Threat Model & Mitigations
- **Threat**: Discrepancy between PySpark outputs and standalone simulation fallback outputs.
  - *Mitigation*: Both engines use identical formulas and breakpoints; integration tests verify numerical equivalence within epsilon < 1e-4 against golden fixtures.
- **Threat**: Outlier values or zero variance in weather variables causing division by zero in Pearson correlation.
  - *Mitigation*: Standalone and Spark formulas check for zero variance and null inputs, returning null r with Low confidence tier.
- **Threat**: Incomplete window calculation at beginning of dataset emitting incorrect AQI.
  - *Mitigation*: Strict enforcement of >=16 valid hours rule; windows with <16 hours are suppressed with INSUFFICIENT_VALID_HOURS.
