# Plan 04-01: Backend-Frontend Wiring & Contract Reconciliation

## Goal
Connect the Next.js 15 interactive frontend dashboard (`frontend/`) to the SkyWatch REST API and static data lake (`output/published/api/v1/*.json`), reconcile schema contracts between backend exports and Zod validators, and wire all 5 frontend views (Overview, Stations Map, Analytics, Alerts, Methodology) to live analytical data.

## Context & Requirements
- **OPS-01**: Next.js 15 interactive dashboard featuring Overview, Stations & Map, Analytics, Alerts & Reports, and Methodology wired to backend REST API (FR-29).
- **OPS-02**: MapLibre GL geospatial station map colored by CPCB category with freshness indicator badges (`Fresh`, `Stale`, `Offline`) (FR-30).
- **OPS-03**: Exportable, downloadable CSV reports directly from the UI and static lake endpoints (FR-31).
- **OPS-04**: Render source attribution (OpenAQ, Open-Meteo, CPCB) on footers, engine transparency banners (simulation warning), and visual badges when feeds are empty or stale (>3h) (FR-32, FR-33).
- **Security Boundary**: No client-side OpenAQ API key exposure; frontend requests only internal SkyWatch API endpoints.

<action>
1. Update `frontend/lib/schemas.ts` to reconcile field naming between backend output and frontend types:
   - `metaSchema`: Ensure `profile` ('modern' | 'lab'), `engine` ('APACHE_SPARK' | 'APACHE_PIG' | 'STANDALONE_PYTHON_SIMULATION'), and `is_simulation` (boolean) are accepted.
   - `stationSchema`: Support `station_id` (with fallback to `id`), `last_measurement_time_utc` (nullable ISO-8601 string), and `freshness_status` enum (`Fresh`, `Stale`, `Offline`, supporting both title-case and lower-case).
   - `indexSchema`: Verify 24-hour rolling AQI fields, CPCB category enum, `is_partial`, and `suppression_reason`.
   - `hourlySchema`: Support `hour_of_day_utc`, `ist_time_range` (e.g. "08:30 - 09:30 IST"), and `ist_label` alongside `hour_of_day`.
   - `statSchema`, `dailySchema`, `correlationSchema`, `alertSchema`, `qualitySchema`: Ensure exact match with `config/schemas.yaml`.
</action>
